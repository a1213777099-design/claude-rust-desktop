## 2. 分层架构

系统采用**三层架构**，层间通过明确定义的接口通信：

| 层级 | 技术栈 | 职责 |
|------|--------|------|
| **前端层** | React 18 + TypeScript + Vite | UI 渲染、用户交互、状态管理 |
| **桥接层** | Tauri IPC + Axum HTTP + SSE | 前后端通信、API 路由、流式推送 |
| **后端层** | Rust + Tokio + SQLite | LLM 推理、业务逻辑、数据持久化 |

### 2.1 通信协议

```
前端 → 后端 (两种途径):
1. Tauri IPC (invoke) : 用于原生能力 (文件对话框、窗口管理、系统信息)
2. HTTP REST : 用于业务逻辑 (对话、记忆、项目管理)
   → 通过 Bridge Server (Axum, port 30080)

后端 → 前端:
1. Tauri Events : 原生事件推送
2. SSE (Server-Sent Events) : 流式对话响应
3. HTTP Response : 普通 API 响应
```

## 4. 关键设计决策

1. **Bridge-First 架构**: 使用独立的 Axum HTTP 服务器作为主 API 网关，而非直接依赖 Tauri IPC。这使得前端可以在浏览器中独立开发调试，也便于未来支持 Web 客户端。

2. **双引擎策略**: 同时支持 Anthropic Messages API 和 OpenAI Chat Completions API，通过 ProviderManager 统一路由，支持自定义 API 网关。

3. **可插拔存储**: MemoryStorage trait 定义了抽象存储后端，当前为 SQLite 实现，可替换为向量数据库。

4. **流式优先**: 所有 LLM 交互通过 SSE 流式传输，支持 Text/Thinking/ToolUse 等多种事件类型。

5. **沙箱执行**: 代码执行和敏感操作通过沙箱隔离，防止恶意操作。
